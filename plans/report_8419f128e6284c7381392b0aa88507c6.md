## 本轮选题

- 选中整改项：删除 WebUI TTS 全链路，并移除 Header/Tools 的 `Voice replies` 入口。
- 选择原因：
  - 它是喷点报告高优先级项里边界最清晰、ROI 最高、最不依赖额外调研的一项。
  - 它直接服务于“把主产品从弱价值表层功能收回来”，而不是继续给 WebUI 增加小系统。
  - 当前代码链路集中在 `webui-src`，不触碰 manager/task/plan 真相源协议，闭环最稳。

## 为什么这项符合项目目标

- 项目目标要求主系统聚焦“异步自治作业编排”，而不是继续拉宽 WebUI 表层能力。
- TTS 并不承担任务编排、状态治理、验收门禁或离线闭环中的关键职责，只是附加表层体验。
- 删除后，WebUI 仍保留在线操作所需的核心界面：状态展示、Plans/Tasks 对话框、消息流、删除模式、重置与重启确认。

## 为什么本轮不处理其他高优先级喷点

- WebUI 其他控制面：`Delete messages / Reset / Restart` 仍直接落在现有在线操作面上，当前证据不足以和 TTS 一起打包删除。
- `plan.effect.taskTemplate`：需要动到编排合同与持久化 schema，虽然 ROI 高，但闭环明显比本轮大。
- 状态真相源 / SSE / focus：都属于“先澄清边界再动手”的问题，本轮若直接写会超出最小整改。

## 简明自评审

- 不过度设计：本轮没有把 TTS 替换成别的播放器、无障碍抽象或配置开关，只做整链删除。
- 不明显削弱能力：删除的是非主线附加功能，不影响消息读写、任务/计划查看、toast、删除模式、重启/重置操作。
- 稳定闭环：删掉入口、运行时依赖、只为 TTS 存在的 helper 与对应测试后，链路不存在半残留状态。
