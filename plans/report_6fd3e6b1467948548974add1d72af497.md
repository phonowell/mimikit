## 候选比较与自评审

### 选择项

- 选择：压缩 `plan.effect.taskTemplate`

### 为何选它

- 直接命中路线图任务 3，且前两轮已清掉其前置项。
- 改动集中在 plan effect 类型、payload 和少量测试 helper，不会扩成 SSE/WebUI 或 manager 主链重构。
- 可以立即减少 plan/task 双持有的重复语义，又不影响 manager 在触发前看到计划合同摘要。

### 为何暂不做其他候选

- `SSE/WebUI projection` 需要先有更稳定的 plan/task 合同边界，否则只是在粗投影上继续补洞。
- `manager 阶段图 / tests 减码` 属于更后置的只读/重构任务，现在提前做只会把未稳定的合同再次摊开。

### 不过度设计判断

- 没有新增新模块或配置项。
- 没有让 plan 直接读取 spec 文件，也没有把 prompt builder 改成异步链路。
- 只把原先散落在 `taskTemplate` 的重复字段压成两个根部字段：
  - `taskKey`：单一稳定 digest，负责计划去重
  - `taskContract`：供 prompt payload 暴露的合同 digest

- `src/work/types/task-runtime-types.ts`
