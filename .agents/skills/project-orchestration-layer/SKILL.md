# Project Orchestration Layer

## 硬触发条件
- 仅当用户在当前会话中手动明确要求启用时可用（例如：`你是编排层`、`orchestration layer`）。
- 禁止自动触发：不得基于关键词扫描、历史上下文继承、或模型推断自动进入本 skill。
- 当前分支必须是 `main` 或 `worktree-{1,2,3}`；任一条件不满足时不启用并说明原因。

## 角色边界
- 默认只做必要编排：`main` 为编排模式，`worktree-{1,2,3}` 为等价智能执行模式。
- 在 `main` 一律禁止直接修改业务代码（包括小改动/顺手修复）。
- 业务代码改动必须派发到 `worktree-1/2/3` 槽位执行。
- 并行上限固定为 `3`，与 `worktree-1/2/3` 一一对应。
- 所有实现默认全量更新，不留兼容层；如有必要需同步更新相关文档。

## 执行前硬闸门
- 任何编辑动作前必须执行：`git rev-parse --abbrev-ref HEAD` 与 `pwd`。
- 仅当“目录=~/Projects/mimikit-worktree-{1,2,3} + 分支=worktree-{1,2,3}”同时成立，才允许进入实现流程。
- 未通过即立即降级为“仅编排模式”，只允许任务拆解/派发/状态汇报，禁止实现与提交。

## 防漂移机制
- 每轮回复必须显式声明：`模式=<编排|实现> | 分支=<branch> | 槽位=<worktree-x|none>`。
- 声明缺失、字段不全、或状态与硬闸门不一致：本轮自动降级为“仅编排模式”，禁止进入实现。
- 上下文切换后（切分任务、切槽位、准备编辑）必须重新执行硬闸门，不得复用旧结论。
## Plan 隔离硬约束（可执行检查）
- 事实边界：`main` 与 `worktree-1/2/3` 的 `plans/` 互相隔离；任一工作区本地 `plans/` 仅代表本工作区状态，禁止作为跨槽位真相源。
- 派发/交接必检：任务卡必须携带 `plan_id/当前步骤/已完成/下一步/阻塞` 摘要；仅给另一个工作区的 `plans/...` 路径引用视为不合格并拒绝派发。
- 收敛必检：是否可 `wt-land` 仅依据当前槽位本地证据 `git status --short`、`git diff --stat`、`lint/type-check/test` 结果判定；`main` 或其他槽位 plan 状态不得替代门禁结论。
## 越界复盘与防复发规则
- 已知根因：把临时修复误判为编排动作，且编辑前未确认槽位，导致在 `main` 直接实现。
- 防复发主规则：未通过硬闸门前，任何“实现型动作”一律不可执行。
- 违例判定：`main` 出现业务实现 diff（新增/修改/删除）即视为越界，不以改动大小豁免。
## 分配防抖策略
- 默认防抖：用户新需求到达后，分配前固定等待 `30s`，观察是否有补充信息。
- 计时重置：`30s` 窗口内出现新增约束/补充需求时，重置为新的 `30s` 并按最新输入收敛任务卡。
- 提前派发例外：用户明确“立即执行”、已有阻塞方在等待、或防抖窗口超时。
- 低 token 一致性：防抖仅做单次 `30s` 等待，禁止长等待与高频轮询；到点未补充即派发。
- 里程碑记录：每次分配必须记录 `是否触发防抖/等待时长/触发派发原因`。
## 里程碑前置检查清单
1. 分配前
- 当前为编排层触发态（用户明确要求 + 当前分支 `main`/`worktree-{1,2,3}`）。
- `worktree-1/2/3` 均可访问，槽位职责与文件边界无交叉。
- 任务卡字段完整：目标、文件边界、验收命令、禁止项、`plan_id/当前步骤/已完成/下一步/阻塞` 摘要。
- 防抖状态已判定：触发与否、等待时长、派发原因可审计。
2. 编辑前
- 任一槽位接到新任务卡后，第一步必须执行 `pnpm run wt-rebase`；与 `main` 同步成功前禁止编辑。
- 已执行并通过硬闸门（目录与分支双命中槽位）。
- 本次回复已声明 `模式/分支/槽位` 且与硬闸门一致。
- 若任一不满足：停止实现，回到编排派发。
3. 提交前
- `git status --short` 全量改动已审阅；预期外改动已记录并准备在合并阶段说明，不做范围裁剪。
- 受影响测试已执行并通过；失败项已记录且阻塞提交。
- 提交信息可追溯到槽位任务卡 ID（如 `task-...`）。
4. land 前
- 已执行 `review-code-changes` 且问题闭环。
- 全量门禁 `lint/type-check/test` 在收敛阶段通过；未通过禁止 `wt-land`。
- 无跨槽位依赖时，槽位完成并过门禁即可 `wt-land`；有依赖时按依赖拓扑顺序串行 `wt-land`，不得以 `main` 的 plan 状态跳过本槽位门禁。
## 违例自动处置流程
1. 立即停止：发现 `main` 实现改动后，立刻停止一切编辑与提交动作。
2. 立即回滚：仅回滚本次越界实现改动到 `HEAD` 干净状态，不影响他人既有改动。
3. 记录根因：最少记录 `触发任务`、`越界文件`、`为何绕过硬闸门`、`防再发措施`。
4. 重新派发：生成新的槽位任务卡并指派到 `worktree-1/2/3`（含边界与验收命令）。
5. 恢复执行：从“执行前硬闸门”重新开始，未通过前不得恢复实现。
## 低 Token 协议
- 禁用 `fork_context`，每个 agent 只发最小任务卡。
- 任务卡最小字段：目标、文件边界、验收命令、禁止项、`plan_id/当前步骤/已完成/下一步/阻塞` 摘要。
- 对已启动子进程/agent 的中断先评估浪费，默认不中断；仅在阻塞或目标已变化时中断，且必须记录中断原因与成本。
- 槽位执行默认“少中断 + 继续推进”：非阻塞且目标未变更时持续推进；预期外文件改动先记录影响，冲突集中在 `wt-land` 阶段处理。
- 对 token 极度敏感：优先最小输入、最少轮次，避免重复上下文与无效轮询。
- 编排层默认低耗时 + 少加载：仅在必要时加载相关 skill，优先完成必要编排动作；高耗时任务（全量门禁/大范围扫描/长轮询）延后到收敛或明确阻塞阶段。
- 状态回报只在里程碑触发：`完成`、`阻塞`、`待合并`。
- 对话中仅回：`files changed`、`diff --stat`、`3 条关键点`、`命令结论`；长日志写入本地文件，仅回路径与摘要。
- 槽位内优先跑受影响测试；全量 `lint/type-check/test` 只在收敛阶段跑一次。
## 工作流
1. 预检：仅检查当前分支为 `main` 或 `worktree-{1,2,3}` 且槽位可用；其他检查延后到槽位执行前硬闸门。
2. 分配：按目录边界给 3 个 agent 分槽，避免交叉编辑。
3. 同步：槽位接到新任务卡后首步执行 `pnpm run wt-rebase`，同步成功才可编辑；落地前若 `main` 有新提交需再执行一次。
4. 执行：agent 在各自槽位完成改动与自检。
5. 收敛：统一执行 `review-code-changes`，再跑全量门禁（`lint/type-check/test`）；任一门禁未通过禁止进入 `wt-land`。
6. 回主线：每个槽位执行 `wt-land` 时均使用 `pnpm run wt-land -- --message "..."`；默认推送该槽位当前工作区全部变更，不按“当前工作范围”筛选；预期外改动需记录并在合并阶段说明。无跨槽位依赖时可完成即 land；有依赖时按拓扑顺序串行 land。槽位改动 `land` 回 `main` 后不再重复执行额外门禁。
## 能力缺口处理
- 若出现 skill 生命周期问题（搜索/新增/替换/移除），立即调用 `audit-skill-lifecycle`。
- 若仅为实现细节问题，不触发 skill 生命周期治理，直接按现有能力推进。

## 汇报模板
- 进度：`{当前}/{总数}`
- 分配防抖：`是否触发 | 等待时长 | 触发派发原因`
- 每槽位：`状态 | 改动文件数 | 关键风险(最多1条)`
- 合并阶段：`是否可 land | 阻塞项 | 下一动作`

## 禁止事项
- 禁止把完整会话上下文广播给全部 agent。
- 禁止重复输出相同背景信息与长篇日志。
- 禁止未过门禁直接 `wt-land`。
- 禁止忽略依赖关系执行 `wt-land`；存在依赖时必须按拓扑顺序串行，禁止与依赖链冲突的并发 land。
